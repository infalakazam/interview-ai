# PrepAI (InterviewIQ)

PrepAI is a browser-based interview practice app. Students choose a topic and session length, answer questions, and receive feedback and practice history. The project demonstrates HCI, traditional machine learning, and an iterative SDLC.

## Project layout

- `index.html`, `start-practice.html`, `practice-session.html`, and the other HTML files are page shells.
- `main.js` controls page rendering, practice sessions, adaptive question selection, and the scoring API call.
- `style.css` contains the shared responsive purple interface.
- `questions.json` contains the practice question bank.
- `backend/app.py` exposes the scoring API.
- `login.html` and `login.js` provide Google sign-in; the API verifies Google's signed ID token before creating a local browser profile.
- `Start PrepAI API.bat` starts the backend for you; you do not need to write backend code.
- `train_mohler.py` compares, trains, evaluates, and exports the supervised Mohler model.
- `prepai_mohler_model.joblib` is generated by training and loaded by the API; it is not committed.

Run the frontend with VS Code Live Server (starting at `index.html`) or another local web server. Opening HTML directly can prevent the browser from loading `questions.json`. After Google verifies the sign-in, each account's display name and practice history are stored separately in that browser's `localStorage`; there is no remote user database or synchronization across browsers.

## Deploy online with Render

The included `render.yaml` deploys the frontend and API together as one Render web service. Once deployed, visitors can open the Render URL without running Live Server or starting the API on their own computers. Their practice history remains in each browser's local storage; this deployment does not add a shared database.

1. In the project folder, run `git rm --cached .env` once before committing. This removes the already-tracked `.env` from Git while keeping the local file. Then commit and push the project, including `render.yaml`, to GitHub. Do not commit `.env`; enter the Google Web Client ID as a Render environment variable instead.
2. In Render, choose **New > Blueprint**, connect the GitHub repository, and apply the `render.yaml` configuration. When prompted, set `GOOGLE_CLIENT_ID` to your Google OAuth **Web Client ID** (not a client secret).
3. Wait for the first deploy to finish and copy the service's `https://…onrender.com` URL.
4. In Google Cloud Console, open that OAuth client's **Authorized JavaScript origins** and add the Render origin, with no path (for example, `https://prepai-interviewiq.onrender.com`). If the OAuth consent screen is in testing mode, add each person who needs to sign in as a test user.
5. Open the Render URL. The service serves the login page, frontend assets, and API from the same origin. You do not need to run `Start PrepAI API.bat` or Live Server for the hosted version.

For local development, keep using the setup below. The code automatically uses the local API when the frontend is opened from `localhost` or `127.0.0.1`, and uses the same origin when hosted.

## First-time Google login setup

You do not need to understand or write backend code. The backend is a small PrepAI program that runs in a terminal while you use the site. Google requires a one-time Web Client ID before it will show the real sign-in button.

1. Follow Google's steps to create an OAuth Client ID for a **Web application**: [Get your Google API client ID](https://developers.google.com/identity/gsi/web/guides/get-google-api-clientid).
2. In that Google setup, add the website address shown by Live Server to **Authorized JavaScript origins**. Use the address only, with no page name at the end; for example, `http://127.0.0.1:5500`. If Google asks for test users, add the Gmail account you plan to use.
3. Double-click **Start PrepAI API.bat**. The first run installs the needed Python packages and may take a few minutes. When it asks, paste your Web Client ID (the value ending in `apps.googleusercontent.com`) and press Enter. Do not paste a client secret. The script saves this public ID in the local `.env` file.
4. Keep the black terminal window open while using PrepAI. In VS Code, start Live Server for `index.html`. PrepAI will show the login page; reload it if it was already open.

If you see “PrepAI cannot reach its API,” the black terminal window is closed or the backend did not start. Open it again by double-clicking the `.bat` file. Google verifies the returned ID token on the backend as described in [Google's ID token guidance](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token).

Sign-in gates the app interface and keeps browser history separate for each verified Google account. This prototype does not issue a persistent server session or sync the practice data to a database, so the account and its history are local to the browser.

## Start the scoring API later

After the first-time setup, start the backend any time by double-clicking `Start PrepAI API.bat`. The equivalent command, for users comfortable with a terminal, is:

```powershell
.venv\Scripts\python.exe -m uvicorn backend.app:app --reload --port 8000
```

The frontend sends each response to `http://127.0.0.1:8000/api/score`. Check `http://127.0.0.1:8000/api/health` for model readiness. If no artifact is present, the API returns 503 and the frontend labels its local keyword estimate as a fallback rather than presenting it as an ML score.

Example request:

```json
{
  "question": "Explain the purpose of an index in a database.",
  "reference_answer": "An index is a data structure that speeds up retrieval of rows at the cost of storage and update overhead.",
  "student_answer": "A database index helps find rows faster, but it takes space and can make writes slower.",
  "key_concepts": ["retrieval", "storage"]
}
```

The response contains a 0–100 display score, the Mohler 0–5 prediction, concepts found in the answer, and a recommended next difficulty.

## Adaptive question difficulty

The app averages the current answer score with up to two previous non-skipped scores. An average of 78 or higher recommends one difficulty level up; below 42 recommends one level down; otherwise the current level remains. PrepAI selects an unused question in that topic at the recommended level, or the nearest available level.

This is an explainable adaptive policy, not a second trained model. Mohler provides grades for answers, but it does not label which question difficulty should follow an answer. Claiming a supervised difficulty model without such target labels would not be justified. This policy can be evaluated during HCI walkthroughs and later replaced if suitable interaction data is collected.

## HCI, ML, and SDLC presentation

- **HCI:** Demonstrate topic and difficulty selection, the guided practice flow, question navigation, legible feedback, keyboard focus, and responsive layout. Explain how the feedback and next-question choice support the learner.
- **ML:** Show Mohler preprocessing, TF-IDF, the three regressor comparison, grouped cross-validation, held-out metrics, example predictions, and limitations on interview-answer transfer. Explain that adaptive difficulty is a transparent policy using the model's score.
- **SDLC:** Present requirements, interface and data design, implementation, validation, and iteration. Capture usability issues and document how feedback changed the design.
